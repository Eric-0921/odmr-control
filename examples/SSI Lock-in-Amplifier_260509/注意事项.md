# 注意事项

## 1. 文档用途

本说明用于指导用户在使用 Query Data 程序时，快速判断仪器是否已升级成 liuxi 架构，并选择正确程序，避免因数据格式不一致导致“读数异常”或“解析失败”。

## 2. 适用范围

本说明仅适用于以下四款机型：

- OE2011
- OE2012
- OE2021
- OE2022

以上机型同时存在标准架构和升级成 liuxi 架构的版本，导致 Query Data 程序读回的数据格式存在差异。

## 3. liuxi 架构与标准架构差异

- 标准架构：执行 RALL? 后，返回一组固定长度的数据包（32768 字节）。
- 升级成 liuxi 架构：执行 RALL? 后，返回一段包含多个数据项的字符串（文本格式）。

你在程序端最常见的差异表现：

- 标准架构：接收区表现为固定长度二进制块。
- liuxi 架构：接收区表现为可读字符串，含多个数值字段。

## 4. 架构判断方法

可通过仪器 ID 信息判断是否为 liuxi 架构。

屏幕查看路径：

- 点击 system
- 进入 Info
- 点击 Menu Enter
- 查看 Ver: xxxxxxxxx

示例：

- 标准架构 ID：S25.1210.03-L25.1120.4-A25A
- liuxi 架构 ID：S26.203.13-L26.203.4-A25A

说明：

- liuxi 架构自 2026 年推出。
- 版本号中包含 S26 的机型，均可判定为 liuxi 架构。

快速判断规则：

- Ver 中出现 S26：按 liuxi 架构处理。
- Ver 为 S25 及更早版本：按标准架构处理。

## 5. 程序兼容性说明

- 标准架构和 liuxi 架构均不影响 Single Data、Multi Data 程序运行。

Query Data 程序使用建议：

- 标准架构：
	- 使用 USB、Ethernet 接口时，返回均为固定长度数据包。
	- 建议使用独立程序：OE20XX_Ethernet_Query Data、OE20XX_USB_Query Data。

- liuxi 架构：
	- 使用 RS232、USB、Ethernet 接口时，返回均为包含多个数据项的字符串。
	- 可直接使用：OE20XX_Query Data。

## 6. 用户操作步骤

1. 开机后先进入 system -> Info -> Menu Enter，记录 Ver 信息。
2. 根据 Ver 判断是否为 liuxi 架构。
3. 按架构选择对应 Query Data 程序。
4. 发送 RALL? 指令，观察回包类型是否与预期一致。
5. 若回包与预期不一致，先检查是否选错程序或接口。

## 7. 回包是否正常的判断标准


- 正常（标准架构）：
	- 回包长度稳定，单次约 32768 字节。
	- 程序以数据包方式处理，不应按字符串拆分。

- 正常（liuxi 架构）：
	- 回包为可读字符串，包含多个数据项。
	- 程序可按分隔规则解析多个字段。

- 异常常见表现：
- 把老架构数据包按字符串解析，显示乱码或字段数异常。
- 把新架构字符串按固定包长截断，导致数据缺失或解析失败。
